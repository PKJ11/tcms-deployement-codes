Phase 3 — MinIO

Unlike Postgres, MinIO has no installer wizard — it's a single .exe you run as a service. Do this in an Administrator PowerShell.

1. Create folders for the binary and the data

New-Item -ItemType Directory -Force -Path "C:\minio"
New-Item -ItemType Directory -Force -Path "D:\miniodata"
Why: same reasoning as Postgres — binary and data are kept separate, and the data folder lives on D:, not C:, so it mirrors the disk layout we'll use on the real server.

2. Download the MinIO server binary

Invoke-WebRequest -Uri "https://dl.min.io/server/minio/release/windows-amd64/minio.exe" -OutFile "C:\minio\minio.exe"

3. Register it as a Windows service via NSSM

winget install NSSM.NSSM
Close/reopen PowerShell if nssm isn't recognized right after install, then:

nssm install MinIO "C:\minio\minio.exe" "server D:\miniodata --console-address :9001"
nssm set MinIO AppEnvironmentExtra MINIO_ROOT_USER=tcms_admin MINIO_ROOT_PASSWORD=Tcms@Storage2026
nssm start MinIO

Why AppEnvironmentExtra specifically: MinIO reads its root username/password from environment variables at process startup, not from a config file. Windows services don't inherit the environment variables from your PowerShell session — they run in their own isolated environment — so if you just did $env:MINIO_ROOT_USER=... in your terminal and started the service, it wouldn't see it. nssm set ... AppEnvironmentExtra injects those variables directly into the service's process environment, which is the reliable way to do it without a reboot.

Use the same values that are already sitting in your .env (MINIO_ROOT_USER=tcms_admin, MINIO_ROOT_PASSWORD=Tcms@Storage2026) so the app and the service agree — you'll rotate both together later before this goes anywhere near pr

4. Verify it's running

Get-Service MinIO
Should show Running. Then open http://localhost:9001 in a browser and log in with tcms_admin / Tcms@Storage2026.

5. Create the bucket the app expects

In the MinIO console: Buckets → Create Bucket → name it exactly tcms-documents (matches MINIO_BUCKET in .env).

Impact on the project: every file-upload/download feature in the app (src/lib/storage.ts — content materials, certificates, qualification docs) talks to this bucket
by name. If the bucket doesn't exist or the name doesn't match .envoSuchBucket" error the first time someone tries to attach a file —not at app startup, so it's easy to miss until you actually test that flow.
